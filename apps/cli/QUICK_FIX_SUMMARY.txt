ISSUE FIXED:
-----------
When user pressed backspace to delete the "/" character from the slash menu
query, the menu would stay open. User had to press Esc to close it.

SOLUTION:
---------
Added automatic closing logic when the query becomes empty.

FILES CHANGED:
--------------
1. src/screens/chat-screen.tsx
   - Added auto-close check in SlashPageMenu setQuery callback
   - When query is empty → closeSlashMenu() is called

2. src/components/home-text-area.tsx
   - Added closeSlashMenu to useAppState import
   - Added auto-close check in SlashPageMenu setQuery callback
   - When query is empty → closeSlashMenu() is called

THE FIX:
--------
Before:
  setQuery={(query) => {
    setSlashMenuQuery(query);
    setSlashMenuSelected(0);
  }}

After:
  setQuery={(query) => {
    // Auto-close slash menu if query becomes empty
    if (!query || query.trim() === "") {
      closeSlashMenu();
      return;
    }
    setSlashMenuQuery(query);
    setSlashMenuSelected(0);
  }}

USER EXPERIENCE:
----------------
BEFORE:
  1. Type "/" → Menu opens
  2. Press Backspace → Menu stays open (BAD)
  3. Press Esc → Menu closes (extra step)

AFTER:
  1. Type "/" → Menu opens
  2. Press Backspace → Menu closes (GOOD - automatic)
  3. No need for Esc (better UX)
